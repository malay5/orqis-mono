Final sprint. No new endpoints, no new agents, no new env vars. Everything
shipped here is read-only polish + SEO + launch coordination.

If you're returning to this project after a break: the only thing you need
to manually run before launch is **the build matrix at the bottom**. Nothing

## 1. New public routes

| Path | What it is |
|---|---|
| `/changelog` | Hand-curated release notes, v0.1 → v0.11 (one entry per sprint). Source: `orqis-frontend/src/app/changelog/page.tsx`. Newest first; collapsible details under each release. |

The `NEXT_PUBLIC_SITE_URL` env var (defaults to `https://orqis.xyz`) is
read by both the sitemap and JSON-LD. Set it in `.env.local` if you're
deploying to a different domain.

## 3. Onboarding tour

`OnboardingTour` (`src/components/dashboard/OnboardingTour.tsx`) is a
3-step modal mounted on `/dashboard` (the activity page). It's
localStorage-gated by the key `orqis_tour_v1`.

- Step 1 — credit balance + ledger link
- Step 2 — browse the catalogue
- Step 3 — mint an API key + MCP install

To re-trigger the tour during testing:

```js
localStorage.removeItem("orqis_tour_v1")
// then refresh /dashboard
```

If we revise the steps, bump the storage key suffix (`_v2`, `_v3`, …) so
existing users see the new version once.

## 4. JSON-LD on agent detail pages

`app/agents/[slug]/page.tsx` injects a `SoftwareApplication` schema with
`AggregateRating` (only when `ratingCount > 0`). The price field uses
`priceCurrency: "ORQ"` since credits aren't an ISO currency — Google Search
will accept it but won't show price-rich snippets, which is fine for v1.

When Stripe ships, swap `ORQ` for `USD` and add a real `lowPrice` /
`highPrice` if pricing tiers exist.

## 7. Verification matrix (run this before launch)

PowerShell, from repo root:

```powershell
# Frontend
cd orqis-frontend
$env:NODE_OPTIONS="--max-old-space-size=8192"
npm run build
npx tsc --noEmit

# Backend
cd ..\orqis-backend
npm run build
npx tsc --noEmit

# SDK
cd ..\orqis-sdk
npm run build
node --loader tsx examples/sdk-smoke-test.ts

# MCP
cd ..\orqis-mcp
npm run build
node --loader tsx examples/mcp-smoke-test.ts
```

All five must be green. The frontend OOMs without the heap bump — leave the
`NODE_OPTIONS` baked into `package.json`'s `build` script (already done).

After you push the launch tag, also verify:

- `https://orqis.xyz/sitemap.xml` returns the agent list
- `https://orqis.xyz/robots.txt` references `/sitemap.xml`
- View-source on any `/agents/:slug` page shows the JSON-LD `<script>` block
- `/dashboard` triggers the onboarding tour for a fresh-localStorage browser
